# Abort Long-Running Operations — v0.6.5

## User experience

Whenever a GUI action is running, the main progress panel displays:

- elapsed time;
- an expected limit selector from 5 to 120 minutes;
- a warning after the selected expected limit is exceeded;
- **Stop current operation**.

The expected limit is a visual warning threshold. It does not automatically terminate work. The user remains in control and explicitly chooses whether to stop.

## Cancellation sequence

```text
User clicks Stop current operation
        ↓
GUI sends cancellation request
        ↓
Backend marks operation as cancelling
        ↓
Owned npm/npx/Playwright/Codex process trees are terminated
        ↓
Remote worker jobs receive cancel_requested
        ↓
Python loops stop at their next cancellation checkpoint
        ↓
Operation is recorded as cancelled
```

## API

```text
GET  /api/operations/active
GET  /api/operations/{operation_id}
POST /api/operations/{operation_id}/cancel
POST /api/agentic/runs/{run_id}/cancel
GET  /api/runner-agents/job/status
POST /api/runner-agents/job/{job_id}/cancel
```

The GUI sends these headers on cancellable requests:

```text
X-AstraHeal-Operation-Id
X-AstraHeal-Operation-Label
X-AstraHeal-Expected-Seconds
```

## What is terminated

The operation registry tracks child processes started by AstraHeal. On cancellation it terminates the complete owned process tree, including child Node.js and browser processes where applicable.

Supported managed operations include:

- Playwright test execution;
- generated-test validation and optional execution;
- local and Central-VM parallel shards;
- BrowserStack launcher commands;
- Codex CLI execution;
- npm, npx and build commands;
- Graphify extraction;
- autonomous LangGraph workflows;
- distributed Worker Agent jobs.

## Repository safety

Cancellation does not accept partial uncommitted generation or framework-repair work. Existing backup, validation and rollback controls remain active. Operations that already committed a complete safe output keep that output; a later runtime execution cancellation does not erase valid generated source.

## Remote Worker Agents

Worker Agent packages generated from v0.6.5 poll the Central VM for job cancellation while a command is running. When cancellation is requested, the worker terminates its command process tree and returns the job as `cancelled`.

Worker Agent packages generated by older AstraHeal versions should be regenerated and redeployed to receive remote cancellation support.

## Configuration

No environment variable is required for manual cancellation. The GUI expected-limit selector is a warning threshold only.

For command-specific hard timeouts, existing timeout settings remain authoritative. Manual cancellation can stop the operation before those timeouts are reached.
